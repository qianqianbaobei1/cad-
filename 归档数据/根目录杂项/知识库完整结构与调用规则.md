## 调用规则：每条数据如何被加载

### 加载策略总结

| 策略 | 说明 |
|------|------|
| **索引O(1)** | 启动预热，按ID精确查找，命中则直接返回 |
| **CSV缓存** | 首次访问时全量读入内存，后续从内存读，直到服务重启 |
| **按需加载** | 只在流水线执行过程中按需读取，不预热 |
| **静态JSON** | 启动或首次调用时一次性加载到全局变量 |

## 关键注意事项（拷贝时必读）

### 1. T3物料CSV有两个位置，内容需保持一致

| 位置 | 读取者 |
|------|--------|
| `标准知识库/源数据/02_通用安装工程/CSV导出/02_t3_标准物料库.csv` | **服务端运行时** |
| `标准知识库/T3_安装_标准物料库.csv` | 工具脚本、CLI（流水线测试.py） |

两个文件内容相同（互为副本），修改时要**同时更新**。

同样：
- 房建T3：`01_房屋建筑.../CSV导出/03_t3_...csv` ← `标准知识库/T3_房建_...csv`
- 品类节点：`06_品类树/品类节点索引.csv` ← `标准知识库/品类节点索引.csv`

### 2. 索引目录是运行时依赖

`项目数据/本地知识库包/索引/` 下的5个JSON（385MB）是服务端的O(1)查询层。用 `构建索引.py` 从源数据CSV生成。拷贝后如果CSV有变化，需重建索引。

### 3. 三级分类材料库是匹配核心

`标准知识库/三级分类材料库.json`（16MB）是材料名→CCE分类的匹配引擎。包含：
- `categories`: 1030个末级分类
- `materials`: 18310种标准材料
- `name_index`: ~28063个别名/材料名→分类映射

### 4. 这些文件实际未被运行时加载

拷贝时可省略以减小体积（除非需要离线参考）：

| 文件 | 大小 | 原因 |
|------|------|------|
| `源数据/04_采购拆解平台/` | ~8MB | 过程文档，代码不加载 |
| `源数据/05_品类树损耗率/` | ~200KB | 有CSV覆盖明细可用，JSON未加载 |
| `源数据/省份适配/` | ~50KB | KB_PROV路径已定义但代码未调用 |
| `标准知识库/N3_规范库.json` | ~10MB | 未加载 |
| `标准知识库/N3_参数追溯表.json` | ~5MB | 未加载 |
| `标准知识库/安装工程_外部物料参考.json` | ~400KB | 仅生成脚本使用 |
| `过程数据/` | ~26MB | 中间产物，运行时不需要 |
