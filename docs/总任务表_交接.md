## 一、规则（防止改乱，必须遵守）

1. **一人一分支一副本**：每个任务从 `fix/catalog-plan-ranges` 拉自己的分支，在自己的 git worktree 里改：
   `git worktree add .worktrees/<任务名> -b task/<任务名> fix/catalog-plan-ranges`
2. **只改本任务“可改文件”列出的文件**。需要改别的文件，先停下告诉统筹人。
3. **只提交到自己的分支**；不合并、不推送、不改写历史、不切别人的分支、不用 `git stash`。
4. **合并只由一个统筹人做**，一次一个分支：`git rebase fix/catalog-plan-ranges` → 全量 pytest → 浏览器抽查 → `git -C <主仓库> merge --ff-only <分支>`。合并完再处理下一个分支（下一个要先 rebase）。
5. **Codex 只负责推送到云端**，不改代码。
6. **worktree 里需要的软链接（绝不提交，已在 `.git/info/exclude`）**，在 worktree 根目录执行（M=主仓库路径）：
   ```bash
   ln -s $M/.venv .venv; mkdir -p integrations/acadrust; ln -s $M/integrations/acadrust/target integrations/acadrust/target; ln -s $M/integrations/cadcraft integrations/cadcraft; ln -sf $M/backend/data/price_library.db backend/data/price_library.db; for f in $M/backend/fixtures/ruler/drawings/*; do ln -sf "$f" backend/fixtures/ruler/drawings/; done; ln -s $M/backend/fonts backend/fonts
   ```
   建完先跑 `cd backend && ../.venv/bin/python -m pytest -q`，应为 433 passed（或当时集成分支的数字）。
7. **不要动**：`backend/fonts/`（含授权字体，绝不能提交/推送）、`price_library.db`（只读）、客户图纸与报价单真值（只读，绝不进仓库）、用户正在用的 8000 端口服务。自测起服务用自己的端口（8020 起）和自己的 `EXTRACTOR_DATA_DIR`，`ENV=development`，`ADMIN_INITIAL_PASSWORD` 设随机测试密码。
8. **原则**：不编造价格/型号/尺寸/状态；识别不出、匹配不上就如实显示“—”“缺价”“待核对”。不要假按钮：每个按钮要么真能用，要么删掉。
9. 提交信息结尾加作者署名行（各代理按自己的规范）。全量测试不得新增失败。
