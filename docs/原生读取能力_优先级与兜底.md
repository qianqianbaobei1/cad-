# 图纸原生读取能力：优先级、兜底与数据导出

> 实现：`backend/extractor/native_takeoff.py`（新模块），接入点在 `backend/extractor/cad_extractor.py`（箱柜/回路识别主链路）与 `backend/app.py`。测试：`backend/tests/test_native_takeoff.py`（11 项）。
> 依据：`docs/逆向分析_CAD快速看图_兼容性与读取能力.md` —— 快速看图对每类对象单独解析、不依赖视觉，这里按同样思路补齐我们的原生链路。
> 开关：`EXTRACTOR_NATIVE_SUPPLEMENT=0` 可整体关闭本次接入（应急回退、对比基线用）。

## 〇、接进识别主链路的部分（重点）

导出只是附带；关键是识别箱柜、回路时用上这些读取能力。`extract_cad_table_data` 里接了两处：

1. **补文字**（`extraction_supplements`）：表格 ACAD_TABLE 图形块里的文字、多重引线、代理对象（天正等，含天正解密）、MINSERT 阵列其余副本 → 并入识别文字池；ACAD_TABLE 网格 → 并入 GTable 表格解析。尺寸标注不并入（纯数字会干扰回路识别）。
2. **原生箱柜清单**（`native_box_inventory`）：按图上写明的三类线索列出“有哪些箱柜”，补上版式规则漏掉的：

   | 线索 | 例子 | 作用 |
   |---|---|---|
   | 系统图标题：箱号 + 名称（含箱/柜/屏） | `02AP01 配电总箱1` | **确认**：规则没认出就补成箱柜（台数、回路待核对） |
   | 平面图配电箱图例属性 = 箱号（天正设备块） | 属性值 `02AL01` | 佐证 |
   | 平面图回路标注“箱号:回路号” | `02AL01:N1` … `N10` | 佐证 + 平面回路数（只含去负载回路，是下限） |

   只在平面图出现、没有系统图标题的编号不直接算箱柜，列入待核对“请确认是否需要报价”。名称是说明句子、以“#”序号开头、或编号是额定值（40AH、630A）的一律排除。

**用客户正式报价单做真值的实测**（四川中烟项目原图，报价单 148 台柜）：

| 图纸 | 接入前：识别箱柜 / 在报价单里 | 接入后 | 说明 |
|---|---|---|---|
| 02-锅炉房 | 5 / 5（报价单上锅炉房的 8 台 02 系列柜 **0 台**） | **13 / 13**（8 台 02 系列柜全部找回，无误报） | 系统图标题与平面图都写明了箱号，版式规则没认出 |
| 01-制丝工房-动力 | 13 / 1 | 13 / 1（无新增误报） | 报价单上 01 系列柜的系统图大多在照明图里；动力图平面出现的 01CZZ01、01KT01 等进入“请确认是否需要报价” |
| 00-总图 / 03-消控室 | 1 / 1、2 / 2 | 不变 | 原本就没漏 |

同时查明：这几张图的 ACAD_TABLE 都是**负荷计算表**（Pe / Kx / CosØ / Pjs），不承载回路，所以补表格文字对箱柜数没有影响；**漏箱柜的根因在“文字 → 箱柜/回路”的版式规则，不在文字读不到**。断路器数量要准，仍需按系统图版式读回路（平面图回路数只是下限）。

## 一、结论：能原生读到的，就不做视觉识别

| 图纸 | 文字 | 表格 | 量（设备数 / 线长） | 是否需要视觉 |
|---|---|---|---|---|
| DWG / DXF | ✅ 原生全读 | ✅ ACAD_TABLE 从图形块还原；线框表用 GTable | ✅ 图块计数、图层线长 | 只在原生门禁不过时兜底 |
| PDF（CAD 直接打印，带文字层） | ✅ 文字层 | ✅ 矢量线框（候选） | ✗ | 用于结构理解，文字可交叉核对 |
| PDF（文字转曲） | ⚠ OCR 兜底（独立证据，需核对） | ✗（表与电路线连在一起，需框选） | ✗ | 主要依赖视觉，OCR 做交叉核对 |
| 图片 | ⚠ OCR（待接） | ✗ | ✗ | 依赖视觉 |

## 二、读取优先级与兜底顺序

### DWG / DXF
1. **DWG → DXF 转换**：LibreDWG → 失败转 acadrust（已有，`cad.dwg_to_dxf`）。转换报错写进读取概览。
2. **原生对象全量读取**（本次新增，按快速看图的解析器清单补齐）：

   | 对象 | 读法 | 原来是否读 |
   |---|---|---|
   | TEXT / MTEXT（模型空间） | 原文 | ✅ |
   | 块属性 ATTRIB（顶层块） | 原文 | ✅ |
   | **块内部文字**（含嵌套块，4~6 层） | 块定义按块名缓存，引用时矩阵变换 | ❌ → ✅ |
   | **嵌套块属性** | 同上 | ❌ → ✅ |
   | **阵列块 MINSERT** | 按行×列展开 | ❌ → ✅ |
   | **尺寸标注显示文字** | 读标注图形块（*D）里实际显示的文字 | ❌ → ✅ |
   | **多重引线** | 读引线内容 | ❌ → ✅ |
   | **表格 ACAD_TABLE** | LibreDWG 读表格对象常报错；改读表格图形块（*T）→ GTable 还原行列 | ❌ → ✅ |
   | **代理对象**（天正 / 浩辰 / 中望自定义对象） | 炸开代理图形；没保存代理图形的如实告警 | ❌ → ✅ |
   | 布局空间文字 | 逐个布局读取 | ❌ → ✅ |

3. **天正文字解密**：代理/天正对象里的加密中文（`tangent.py`，另一会话正在按逆向结果修复）。
4. **原生门禁不过** → 渲染 PDF → 视觉模型（已有流程不变）。

### PDF
1. **文字层**（CAD 直接出的 PDF）。
2. **文字层为空 → OCR**（本次新增，tesseract，本机已装）：整页按长边约 9000px 渲染、分块识别（小字靠放大），只保留含字母/数字/汉字且置信度 ≥ 55 的结果。作为 `ocr` 独立证据接入交叉核对（配置白名单里早有 `ocr`，此前从未产生过）。可用 `EXTRACTOR_OCR=0` 关闭，`EXTRACTOR_OCR_MAX_PAGES`（默认 40）限制页数；结果缓存在 `<pdf>.ocr.txt`。
3. **视觉模型**（已有流程）。

## 三、“量”的原生来源

| 量 | 读法 | 用途 |
|---|---|---|
| **图块统计** | 模型空间顶层同名块引用次数；MINSERT 按行×列；动态块（*U）找回原块名；附块内文字、属性值、块尺寸、是否天正对象 | 平面图设备 / 图例数量。实测：天正设备块属性直接写着设备名，如“双管荧光灯 1284、断路器 552、带保护接点暗装插座 535” |
| **图层线长** | 按图层累计线、多段线（含圆弧段）、圆弧、圆、样条长度；只算顶层，不进块（避免把图例符号线算进电缆） | 电缆、桥架、管线长度。单位未设置时按毫米折算成米 |
| **表格** | ACAD_TABLE 图形块 + GTable 网格还原 | 系统图负荷计算表、材料表、配电箱一览表 |

## 四、数据导出

接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/jobs/{id}/native` | 原生读取概览（JSON）：文字数与来源、表格清单、图块统计前 200、图层线长前 200、字体检查、对象覆盖、告警 |
| GET | `/api/jobs/{id}/native_export` | 下载 Excel《图纸原生数据》 |

Excel 六张表：

| 工作表 | 内容 |
|---|---|
| 读取概览 | 文件、读取路线、单位、各来源文字数、表格数、图块种类/引用数、提示（转换报错、代理对象、缺字体）、对象类型覆盖表 |
| 文字清单 | 序号、文字、来源（TEXT/MTEXT/ATTRIB/DIMENSION/MLEADER/TABLE/PROXY/PDF_TEXT/OCR）、图层、所在块/表格、X、Y、字高、空间 |
| 表格 | 每张表一个区块：来源、位置、行×列，下面是还原后的单元格 |
| 图块统计 | 块名、数量、图层、块内文字、属性值、块尺寸、是否天正对象、是否匿名块 |
| 图层线长 | 图层、线段数、长度（图纸单位）、折合米、构成 |
| 字体检查 | 文字样式、字体、是否可用、大字体、是否可用、使用次数 |

缓存：读取结果按源文件缓存在 `work/native/{id}.json`（放子目录是因为任务列表会扫描 `work/*.json`）；DWG/DXF 任务在处理时就会生成。

前端不放导出按钮（只保留后端接口，供排查与核对用）。

## 六、发现的问题（需要处理）

1. **本机没有任何 SHX 字体**：gbenor / gbcbig / hztxt / tssdeng / simplex 等全部缺失，`simhei.ttf` 也没有。所以我们渲染出的预览，文字都被替换过——这就是“原有字体变了”的直接原因。处理：在 `backend/fonts/`（或 `EXTRACTOR_FONT_DIRS`）放入正版 SHX 大字体与常用中文 TTF；字体检查表会立刻反映。
2. **LibreDWG 读表格对象大量报错**（这张图 2.6 万行错误几乎都是 ACAD_TABLE），表格对象本身不可用；已改从图形块读取。若要读表格的原始结构（合并单元格、列宽），需要更好的 DWG 引擎（ODA 授权或 acadrust 增强）。
3. **转曲 PDF 的表格**：自动切表不可靠，需要“框选区域提表”（与快速看图一致）。
4. **天正文字解密**：`tangent.py` 正在另一会话修复。
5. **全量测试**：424 项全部通过（含新增 11 项）。
