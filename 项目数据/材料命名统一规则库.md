# 材料命名统一规则库

> **用途**: 约束AI在BOQ清单拆解、材料推演、名称校验时的输出行为。
> **数据来源**: 铁建21,300 + 中建全套2,667 + 中建八局3,760 = 合并去重24,499个材料名。
> **版本**: v1.0.0 | 生成日期 2026-05-15

---

## 核心原则（最高优先级）

### 规则0：名称/规格严格分离

采购清单中**材料名称**和**规格型号**是两个独立字段。材料名是**产品名词短语**，规格型号是**纯技术参数**。两者不允许混在一起。

- ✅ 材料名=`薄钢板`，规格=`冷轧08 0.5mm`
- ❌ 材料名=`冷轧08薄钢板0.5mm`（规格参数混入名称）
- ❌ 材料名=`桥架及其配件,结构类型:槽式`（逗号+KV格式应拆到规格字段）

当输入清单本身已经混在一起（如一些中建格式），AI的首要任务是**从混合串中分离名称和规格**，而不是把混合串当作名称原样输出。

---

## 一、名称合法性 — 什么才算"真实材料名"

### 规则1：名称必须是一个物品名词

材料名必须是可采购的**物理实体**或**可计量的商品**。检查方法：
- 能否回答"这是买什么的？" → 能 → 合法
- 能否放到采购合同物料清单里作为一行 → 能 → 合法

```
✅ 预拌混凝土、热轧带肋钢筋、SBS改性沥青防水卷材、断桥铝合金窗
❌ 混凝土浇筑、钢筋绑扎、防水施工、门窗安装（工序描述）
❌ 人工费、运输费、管理费（费用项）
❌ 详见设计图纸、参照规范（引用词）
```

### 规则2：名称长度约束

基于24,499个真实材料名的统计分布：

| 区间 | 占比 | 判定 |
|------|------|------|
| 1字 | ~0% | **不合法** — 无法识别为何物 |
| 2字 | ~3% | **可疑** — 需结合品类上下文确认（如`卵石`、`地漏`可接受，`井台`、`吊轨`需要规格上下文） |
| 3-4字 | ~28% | **纯材料名** — 直接使用（如`薄钢板`、`不锈钢管`） |
| 5-8字 | ~45% | **典型材料名** — 最常用区间（如`热轧带肋钢筋`、`聚合物水泥防水涂料`） |
| 9-15字 | ~18% | **描述型名称** — 允许但需验证是否可简化 |
| 16字+ | ~5% | **过度描述** — 强烈建议检查是否有规格参数混入 |

**输出约束**: 默认输出3-8字的材料名。超过15字必须能在三家中至少一家的数据中找到近似的同名条目，否则判定为规格参数未分离。

### 规则3：名称后缀必须落入合法集合

材料名通常以描述物品类别的名词结尾。以下为三家数据中验证过的合法后缀（高频部分）：

```
电缆 力电缆 电线 钢管 钢板 接头 三通 弯头 法兰 直接
砂浆 混凝土 涂料 卷材 止水带 保温板 砌块 门窗 玻璃
螺栓 螺母 垫圈 焊条 密封圈 垫片 支架 预埋件 连接件
设备 装置 系统 机组 总成 配件 开关 阀门 水泵 风机
传感器 控制器 变压器 断路器 继电器 过滤器 检测仪
```

**输出约束**: 如果AI生成的"材料名"不以这些后缀之一结尾，必须在输出中标注 `confidence=low` 且 `needs_human_review=true`。

### 规则4：名称不包含动作词

以下动作词**绝不应出现在材料名**中（来自三家数据的反模式验证）：

```
新增 拆除 绑扎 浇筑 砌筑 抹灰 铺设 粘贴 拌合 振捣 养护
拆模 压实 组装 调试 接驳 预埋 预留 开挖 回填 夯实 找平 凿毛 切缝 灌浆
```

**例外**: 当动作词作为功能性修饰语且约定俗成时允许：
- ✅ `自密实混凝土`（自密实是性能属性，非动作）
- ✅ `免拆模板`（免拆是产品特性，非动作）
- ❌ `拆除混凝土`（拆除是动作，这是工序不是材料）

### 规则5：名称不能是占位词或引用词

```
禁止的占位词: 其他、待定、详见设计、详见、暂定、参照图纸、由厂家提供
禁止的引用词: 配套XX、随设备XX（应要求甲方提供具体规格）
禁止的投标用语: 自报、报价、投标
```

## 二、命名结构层级 — 材料名是怎么构成的

### 规则6：五级命名结构

所有材料名落入五个层级。AI输出时应明确所处的层级：

```
L1 纯材料名 (3-4字)
   结构: [核心名词]
   样本: 薄钢板、不锈钢管、复合模板、中空玻璃
   占比: 铁建17.8%、中建39.7%
   使用: 规格型号字段承担所有参数

L2 特性+材料 (5-8字)
   结构: [属性修饰] + [核心名词]
   样本: 热轧带肋钢筋、聚合物水泥防水涂料、挤塑聚苯板
   占比: 铁建61.2%、中建42.7%
   使用: 修饰词描述材质/工艺/性能，不可再拆

L3 用途+材料 (6-12字)
   结构: [应用场景] + 用/专用 + [核心名词]
   样本: 桥梁用钢板、流体输送用无缝钢管、低中压锅炉用无缝钢管
   占比: 铁建8.7%、中建1.5%
   注意: 铁建大量使用此模式，中建很少用

L4 品牌/型号+材料 (不定)
   结构: [字母/数字代码] + [核心名词]
   样本: JDG管、KBG管、PVC止水带、HDPE双壁波纹管
   占比: 铁建2.6%、中建2.2%
   注意: 字母前缀是约定俗成的产品代号，不是随意拼写

L5 系统/装置 (>6字)
   结构: [功能描述] + 系统/装置/机组/总成
   样本: 全热交换器系统、消火栓系统、一体化预制泵站
   占比: 铁建6.5%、中建4.0%
   注意: L5是材料集合体，在BOQ拆解时应优先考虑拆分为子材料
```

### 规则7：L5集合体必须尝试拆解

当清单条目本身就是系统级别（如`给排水系统`、`暖通系统`），AI不应直接把系统名当作材料名输出。拆解方向：
- 先检查 `项目默认值库.json` 中该分部(phase)下的 `default_systems`
- 按 system → materials 关系展开为子项
- 最后通过T3标准物料库验证每个子材料的名称合法性

### 规则8：修饰词的排列顺序

当材料名包含多个修饰词时，顺序遵循：
```
[用途] + [工艺/牌号] + [材质] + [形状] + [核心名词]
示例: 流体输送用 热轧 不锈钢 无缝 钢管
      ↑用途     ↑工艺 ↑材质  ↑形状 ↑核心
```

修饰词不得超过3层。超过3层说明规格参数混入了名称。

## 三、反模式 — AI绝对不能输出的

### 规则9：费用/服务项不与材料名混淆

以下关键词出现在输出中时，必须确认该条目是实物材料而非费用：

```
高危后缀: 费、服务（除"服务器"外）、工资、酬金
中建特有反模式: 垃圾清运费用、混凝土费用、料具维修费、打孔费、加工费、
              二次安装费、热浸镀锌费、进出场费、运输保险费
铁建特有反模式: 收费亭（含"费"但是实物）、服务区用广场音柱（含"服务"但是实物）
```

**判定逻辑**: 如果 XXXX费 是一个独立条目（非修饰词），它是费用项，不是材料名。

### 规则10：CI/VI标识类是中建特有品类

中建体系中有独立的CI（企业形象）材料类，包括：
```
CI字 CI牌类 CI旗类 CI架类 CI框 CI灯 CI窗 CI门类 CI棚类 CI标语 CI证类
```

这些在铁建体系中不存在。如果输入的清单来自中铁/铁建项目，不应生成CI类材料。

### 规则11：(定制)标记的含义

铁建数据中1.2%的名称带`(定制)`后缀，含义是该材料为非标加工件。AI在遇到以下情况时应主动标注：
- 材料规格在标准物料库中找不到完全匹配的 → 标注 `is_custom=true`
- 但材料名本身去掉`(定制)`后应仍是一个合法的L1-L4名称

## 四、规格型号格式规则

### 规则12：规格型号的六种基本格式

基于铁建48万条规格字段的统计：

| 格式 | 占比 | 示例 | 适用材料 |
|------|------|------|----------|
| 复合描述型 | 80.7% | `Q235B 800×800mm 45°焊接` | 加工件、非标件 |
| 尺寸型 | 12.6% | `100×50×3mm` | 型材、管材 |
| 型号编码型 | 3.5% | `JDG25`、`YJV-4×25+1×16` | 管线、电缆 |
| 公称直径型 | 1.3% | `DN100` | 管道、阀门 |
| 厚度/长度型 | 1.3% | `0.5mm`、`3000mm` | 板材 |
| 强度等级型 | 0.7% | `C30`、`HRB400E` | 混凝土、钢筋 |

### 规则13：中建KV规格解析规则

中建系统的规格是嵌在物料名称中的，格式为：
```
物料名称,key1:value1,key2:value2,...
```

AI在解析时必须：
1. 以第一个逗号为界，之前为基础名称，之后为规格字段
2. 按 `key:value` 拆解每个规格对
3. 用标准规格键名（见下表）做规范化映射

**标准规格键名表**（来自中建系统，按频率排序）：
```
品种、材质、分类、公称直径、种类、公称压力、规格、接口形式、
型号、规格型号、厚度、尺寸、阀体材质、芯数及标称截面、颜色、
连接方式、驱动方式、强度等级、结构类型、额定电压、阀门类型、
密封面、使用介质、弯度、阻燃等级、桥架规格、类型、长度、品牌、
安装方式、功率、表面处理、钢的牌号代码、额定功率、绝缘电压等级、
额定电流、风量、燃烧性能、控制方式
```

### 规则14：规格值不可写入材料名

AI输出时必须确认以下参数全部在**规格字段**而非**名称字段**中：
- 尺寸：`100×50mm`、`DN100` → 规格字段
- 强度：`C30`、`HRB400` → 规格字段
- 厚度：`0.5mm`、`3mm厚` → 规格字段
- 压力：`PN16`、`1.6MPa` → 规格字段
- 电压：`0.6/1kV` → 规格字段
- 材质牌号：`Q235B`、`304` → 规格字段（除非已是材料名不可分割部分）

**判定标准**: 去掉这个参数后材料名是否仍然完整？→ 是 → 该参数属于规格字段。

## 五、跨企业命名差异 — AI如何适配

### 规则15：三家企业命名偏好对照

| 特征 | 铁建(CRCC) | 中建(CSCEC) |
|------|-----------|------------|
| 名称/规格分离 | **严格分离**，名称纯净 | **混在一起**，需先拆分解 |
| 用途前缀 | 大量使用`XX用XX` | 很少用，倾向短名 |
| 分类体系 | 37个一级品类，偏重铁路/基建 | 云筑三级分类，偏重房建 |
| 独有品类 | 轨道材料、接触网、铁路通信信号 | CI标识、装配式构件 |
| 非标标记 | `(定制)`后缀 | 无统一标记 |
| 名称长度 | 中位数7字 | 中位数4字 |
| 系统级命名 | 较多 | 较少 |

### 规则16：输入源识别 → 输出风格匹配

AI应根据输入清单的来源特征选择输出风格：
- 输入来自**铁路/基建**项目 → 优先匹配铁建命名习惯（含用途前缀、名称较长）
- 输入来自**房建**项目 → 优先匹配中建命名习惯（名称较短、规格用KV格式）
- 输入来源不确定 → 使用铁建命名风格（最规范、名称最纯净）

### 规则17：三家重叠的材料名有最高置信度

三家数据中同时出现的561个材料名（如`不锈钢管`、`PE管`、`交换机`、`全站仪`、`光纤跳线`）是跨企业的通用命名，AI输出这些名称时：
- `confidence=high`
- `needs_review=false`（除非规格参数有问题）
- 优先使用三家中最简洁的版本

## 六、AI输出硬约束（执行规则）

### 规则18：每条材料输出必须包含校验字段

```json
{
  "material_name": "薄钢板",
  "spec": "冷轧08 0.5mm",
  "name_source": "tj_verified | zj_verified | both_verified | ai_inferred",
  "name_level": "L1",
  "name_length_ok": true,
  "contains_action_word": false,
  "contains_spec_value": false,
  "ends_with_valid_suffix": true,
  "has_company_match": true,
  "confidence": "high | medium | low",
  "needs_review": false,
  "review_reason": null
}
```

### 规则19：AI自由推断的名称必须降级

| 来源 | confidence | needs_review |
|------|-----------|--------------|
| `both_verified` — 铁建+中建都有 | high | false |
| `tj_verified` — 仅铁建有 | medium | false |
| `zj_verified` — 仅中建有 | medium | false |
| `ai_inferred` — 三家都没有，AI猜的 | low | true |

`ai_inferred` 的材料会触发 `review_policy` 的 `any_material_source_ai_only` 条件，**不可自动通过Stage 6门禁**。

### 规则20：禁止幻觉材料名

AI不应编造"看起来合理但在三家数据中都不存在的材料名"。如果确实需要推断新名称，必须：
1. 从已有的T3标准物料库中找到最接近的品类
2. 使用该品类下已有的命名模板
3. 在输出中标记 `name_source=ai_inferred` 且 `confidence=low`
4. 提供推断依据（`inference_basis`字段）

### 规则21：默认值库优先于AI推断

当BOQ清单数据很差、特征缺失时，调用 `项目默认值库.json` 的检索策略：
```
match_order: feature_trigger → exact_all_dimensions → partial_dominant_dimensions 
           → phase_default → no_match
```

只有当检索结果为 `no_match` 时，AI才可以自由推理，且必须遵循本规则库的所有约束。

## 七、核验检查清单

AI在输出材料清单前，对每个材料名执行以下检查：

```
□ 名称是物理实体名词吗？（不是动作、不是费用、不是引用）
□ 名称长度在3-15字之间吗？
□ 规格参数都移到了spec字段吗？（尺寸、强度、厚度、压力、电压）
□ 名称后缀在合法集合中吗？
□ 名称不含禁止的动作词吗？
□ 名称不含占位词/引用词吗？
□ 是L5系统级名称吗？→ 尝试拆解为子材料
□ 来源企业特征与输入清单匹配吗？
□ 三家数据中有这个名称吗？→ 设置confidence
□ 如果是ai_inferred，提供了推断依据吗？
```

全部通过 → `can_auto_pass=true`（但Stage 6仍需复核默认参数来源）。
任何一项失败 → `needs_review=true`，不可自动通过。
