# 宿州302 项目知识库说明

这个目录不是最终采购清单，而是材料拆解推理的项目级上下文。

数据流：

```text
BOQ Excel
+ CAD 做法表提取结果
→ 项目知识库
→ 材料拆解工作区
→ 可采纳清单 / 待确认清单 / 缺失资料清单 / 计算追溯表
```

## 文件说明

| 文件 | 作用 | 下游怎么用 |
|---|---|---|
| `boq_items.json` | 结构化 BOQ，包含工程量、单位、原始描述、分类、候选做法类别 | 材料拆解时作为工程量和清单项入口 |
| `practice_rules.json` | 从 CAD 做法表抽提出来的项目做法规则，按楼栋/类别/编号/部位组织 | 给 BOQ 补做法层次、材料证据和部位上下文 |
| `material_mentions.json` | 从做法层文本里抽出来的材料提及，如地砖、防水涂料、水泥砂浆 | 后续接材料主数据，做标准材料名和规格归一 |
| `boq_drawing_links.json` | BOQ 行与图纸做法的候选对应关系，带置信度和命中理由 | 拆料前先确认或筛选哪些做法真正服务某条 BOQ |
| `quality_issues.json` | 解析质量问题，如 OCR 错字、规格脏数据、做法层不完整、BOQ 无图纸候选 | 生成待人工确认项，阻断脏数据直接进采购清单 |
| `manifest.json` | 知识库索引和统计 | 管线入口读取 |

## 当前阶段使用原则

1. `practice_rules.json` 是图纸证据，不是采购清单。
2. `material_mentions.json` 里的 `standard_material_name` 只是种子规则归一结果，后续仍需接材料主数据。
3. `boq_drawing_links.json` 中 `weak_candidate` 不能自动进入可采纳清单，只能作为人工确认候选。
4. `quality_issues.json` 中涉及的做法层不能直接参与 A 级数量计算。
5. 生成材料采购清单时，每条材料必须能追溯到：

```text
BOQ 行
→ 候选图纸做法
→ 做法层
→ 材料提及
→ 数量规则
```

## 下一步建议

优先补：

```text
1. 材料主数据表：把 material_mentions 里的材料名接到标准材料库
2. BOQ-图纸链接确认台：人工确认 boq_drawing_links 的候选
3. 数量规则表：不要把 60%、30%、0.35kg/m² 这类规则写死在采购清单里
4. 四表输出：可采纳 / 待确认 / 缺失资料 / 计算追溯
```
